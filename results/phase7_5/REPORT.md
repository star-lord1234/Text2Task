## 1. Audit findings
* **Tokenizer offsets are exact.** 60 validation rows: 0 stored/fresh tokenisation mismatches, 0 special tokens with offsets, 0 rows with uncovered characters.
* **Gold labels are never mid-word** (0 of 408 validation and 0 train spans), so the model was not taught fragments.
* **The BIO decoder is faithful** to the model's sub-token tags. Fragmentation comes from the model's own labelling, not from an alignment or decoding bug.
* On 458 predicted email spans: 8 (1.75%) start/end mid-word, but 57 (12.5%) are made only of function words (gold: 1.5%), 26 (5.7%) are 1-2 characters, 57 adjacent same-type pairs are separated only by whitespace, and 131 `I-` tags follow `O` (decoded as new spans).
* On 200 predicted spans over the 100 chat messages used in the fixtures: 7.5% mid-word, 16.5% function-word-only, 8.0% one or two characters. Short chat shows 4x more mid-word truncation than emails, which is why Phase 7 looked worse than the email validation numbers suggest.
* Consequence: snapping is cheap but fixes only part of it; function-word fragments and missing phrases need filtering and recovery.

## 2. Step 4 investigation (grammar tooling)
spaCy and NLTK are not installed, and both would add a heavy dependency plus a model/corpus download, so neither was added. The chunker uses closed-class function words plus an explicit action-verb lexicon (about 200 base verbs), with positional evidence for the verb (clause start, after "please", after "to", after a true modal, after a subject, after "let me", gerund after "before/after/until"). Past tense and passives are deliberately not task evidence ("We shipped it", "was cancelled"). Limits: only listed verbs are recognised in a bare imperative; no real parser, no noun-phrase understanding, English only.

## 4. False positives, misses and remaining limitations (as observed)
* **False positives (hybrid, 3 cases):** "Bianca, call me after the meeting." keeps a neural "the meeting" task (the word *meeting* counts as a verb) and links it; "I'll upload the screenshots tomorrow." and "Loading the data is waiting on…" leave a stray fragment ("upload", "load the"/"data").
* **Misses (causes not all diagnosed):** the edge in "Deployment can't start until the test server is set up" (probably the reconciler's lexical matching: *deployment* vs *deploy*); the task and edge in "Before we publish the article, someone must fact-check it" (the hyphenated verb is not in the lexicon, presumably); the edge in "Anushree, run the tests after the build server is configured" and in "Loading the data is waiting on the staging database"; "circulate it" after "then Anushree should" (task found, edge missing); "send it to finance" after "Please finalize the budget before …" (the task was not created). Edges to existing tasks depend on lexical matching between the clause and an existing title.
* **Cue weaknesses that are not new:** "Would Monday work instead of Thursday?" is read as a reassignment (the Phase 5 "instead of" cue); "Forget the sales figures, we don't need them." and "Never mind, we don't need X anymore" do not always cancel.
* **Expectation disagreements, not fixed:** whether "send the invoice tomorrow" or "schedule the retro for Thursday morning" gives a *due* date or a *scheduled* date is a Phase 4 policy question; two fixtures expect a due date and score as misses.
* **Vocabulary-bound:** recovery works only for verbs in the lexicon or with positional evidence; unusual verbs are missed. Fixtures are short English chat messages in the author's own phrasing, so the held-out numbers are optimistic for real conversation.
* **hybrid ≈ rule_only.** On these chat messages the rules do most of the work: rule-only matches hybrid on the new set and is within 1 case on the holdout. The neural models contribute little here and noticeably more on emails (PERSON and TEMPORAL spans). Do not read the hybrid result as evidence that the neural entity model is good.
* Dependency direction follows the wording, not world knowledge. Several sentences can link to the wrong existing task if titles share words.

## 5. How the evaluation was kept honest
1. The development fixture keeps the exact Phase 7 inputs. The new fixture was written **before** any refinement code. Its first run was saved untouched (`first_run/`): hybrid scored 14/34 there.
2. Failures in that run were generic bugs in my own stages (verbless clause fragments counted as tasks, fragments blocking phrase extension, an unreachable "let me" branch, no way for a clear imperative to pass the Phase 5 creation gate, owners leaking across clauses). I fixed those; the new set is therefore **used**, not held out.
3. A **holdout** of 30 fresh cases was written before those fixes and executed only after them (`holdout_first_look/`). One later precision fix (past tense and passives are no longer tasks) came from a unit test; it did not change any holdout number (verified).
4. Mutation checks confirm the key negative tests fail when their guard is removed (ownership/count for acknowledgements, shared-object requirement for completion, clause boundaries for owner scoping).
